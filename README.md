Project Overview & ObjectivesThe goal of this project was to build a clean, multi-page business website for Noluloves Cafe using standard HTML5 and an external CSS3 stylesheet. The site needs to display the cafe's core services, highlight its menu options, show open hours, and use a functional contact form for user questions.  The development workflow was split into clear project phases:Researching competitor cafe websites and planning user paths.  Setting up a clear multi-page site navigation menu.  Writing semantic markup and layout rules.  Testing the layout to ensure it scales correctly on mobile viewports.  2. Design DecisionsA custom styling scheme was used to give the cafe site a distinct, clean look:Background Color (#fff1f5): A soft, pale pink used as the main body background  to match a cafe theme without looking overly corporate.  Card & Section Blocks (#ffffff): Solid white containers used behind text blocks and grid cards  to create high contrast and keep the site readable.  Headers & Text Color (#8f3346): A deep berry red applied to titles and main text elements to build a solid visual hierarchy.  Body Copy (#6f5c58): A dark charcoal-brown shade for standard paragraphs  to make reading easy on the eyes.  Fonts: Global typography is set to "Zalando Sans Expanded", sans-serif;  to keep the font modern and structured.  3. Website Pages & Content BreakdownTo meet the project criteria, the site structure is split into four separate files linked together in the main menu:  index.html (Home): The main landing area. It contains a basic hero section, a short introductory statement, an image, and a call-to-action button.  about.html (About): Houses the background details of the business, focusing on the company story and values.  services.html (Services): A structured layout detailing the catalog items, coffee options, and workspace amenities.  contact.html (Contact): Contains the static location details, business opening hours, and an input form for customer messages.  4. Technical Approach4.1 HTML MarkupThe site layout uses semantic HTML5 tags rather than stacking generic structural blocks:  Layout dividers use explicit <header>, <nav>, <main>, <section>, and <footer> tags.  Text sizes follow a standard visual hierarchy starting with <h1> for page names down to <h3> for subheadings.  Every graphic element includes descriptive alt tags for accessibility and image recovery.  4.2 CSS Layout ArchitectureAll layout rules are kept inside a standalone external file (css/styles.css). The site uses CSS Flexbox instead of old grid systems or floats:  Overflow Handling: The html and body levels use an explicit overflow-x: hidden; rule to stop accidental horizontal scrolling on smaller viewports.  Flexible Card Sizing: Component rows use a flex shorthand property set to flex: 1 1 280px;. This tells the engine to spread items evenly across the page while maintaining a solid baseline width constraint of 280 pixels.Responsive Layouts: A layout media query is defined at an 800px screen break. When a screen width drops under this limit, horizontal rows automatically stack into single vertical columns (flex-direction: column).  5. Challenges Faced & Future Upgrades5.1 Challenges & SolutionsDuring layout testing, image sizes were originally breaking out of their flex containers on narrow mobile widths, creating a horizontal clipping error. To resolve this, a responsive image global rule was added:CSSimg {
  max-width: 100%;
  height: auto;
}
This forces all graphics to automatically scale down to match the width of their parent container while keeping their native aspect ratio perfectly intact.  5.2 Future UpgradesBecause this module is restricted purely to core HTML and CSS, future iterations would focus on:  JavaScript: Adding a validation script to handle the contact form submission data without reloading the active page view.CSS Variables: Switching color tokens into reusable root properties to make updating the palette or adding a dark mode switch faster.
